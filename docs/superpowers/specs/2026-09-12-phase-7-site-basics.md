## 2. Decisions and causes

| Decision | Cause |
|---|---|
| New pages are `pages/{id}` docs (`{title, body(rich), published, updatedAt}`) with code defaults in `js/page-defaults.js`, edited from one admin card **📄 পাতা** | Same "nothing static" rule as Phase 6: the owner edits, never fills from blank; one card for nine pages instead of nine cards. |
| Static head tags are literal per page (title/description/OG/canonical/JSON-LD) even though strings are admin-editable | Scrapers and Google do not run JS (GitHub Pages has no server render). The static values are the defaults; `document.title`/description still follow admin overrides at runtime. A `scripts/sync-head.mjs` regenerates the static head from `STRINGS` + `page-defaults` so they never drift (run in CI, fails the build if stale). |
| OG image: one static `assets/og/<page>.png` per page generated by `scripts/gen-icons.mjs` (canvas: theme ground + ॐ mark + page title); the admin `ogImage` slot, when set, is used at runtime only | Static file is what WhatsApp sees; runtime slot keeps the "everything editable" promise for in-app previews and future hosting with server render. |
| Static shell = real markup for nav/footer/hero *frame* with the default strings, then hydrated in place (`replaceChildren` only on the parts whose data differs) | Kills CLS 0.997 → ≤ 0.1 and gives a first paint without Firestore; JS-off visitors see the frame + a "লোড হচ্ছে" note instead of `…`. |
| Service worker caches only same-origin app shell files (HTML, CSS, JS, fonts, icons) with a version string bumped by `scripts/bump-sw.mjs` (checked in CI); Firestore/Storage/Auth/gstatic requests are never intercepted | Offline-first lessons: cache-key discipline; Firestore already has its own persistent cache; intercepting Auth breaks OTP. |
| `errors` collection: `allow create: if request.resource.data.keys().hasOnly(['message','url','ua','at','stack']) && sizes bounded; read admin only; no update/delete` | Client-side error reporting without a third-party account; bounded fields limit abuse; App Check (owner) will gate it further. |
| Scheduled backup = GitHub Actions cron calling a Node script with a service-account secret `FIREBASE_SA` writing a dated JSON to a private GitHub release/artifact | No new infra; the owner only adds one secret (documented). The workflow is committed `workflow_dispatch` + cron and no-ops with a clear message when the secret is absent. |
| Restore = flip `deleted:false` (audit row `restore`); the rules already allow admin updates and forbid deletes | Soft-delete was the design since Phase 0; restore is its missing half. |
| Masked re-auth = in-page `<dialog>` with `type=password` replacing `prompt()` | `prompt()` shows the password in clear text on phones. |
| CI runs on `ubuntu-latest` with Java 21 + firebase-tools + Playwright Chromium; e2e uses the same `npm run seed` flow | Same gate as local, no new tooling. Rules deploy stays manual (`scripts/deploy-rules.sh`). |

## 3. Data model additions

```
pages/{id}     {title:{bn,en}, body:{bn,en} (rich HTML), published, deleted, updatedAt}   ids: privacy, refund, trust, contact, faq, news(intro), downloads(intro), notfound
errors/{id}    {message ≤ 500, url ≤ 300, ua ≤ 300, stack ≤ 2000, at}                       create: anyone (bounded) · read: admin · no update/delete
albums/{id}/photos/{id} + alt:{bn,en} (optional; caption used when absent)
settings/site  + trustees:[{name:{bn,en}, role:{bn,en}}] (for trust.html; defaults from officers)
```
Indexes: `pages` published+deleted (single-field ok, no order) — none needed beyond the automatic ones; `errors` `at desc` for the viewer (composite not needed).

## 4. Security
- `pages`: read `published && !deleted` or admin; write admin + `hasDeletedFlag()`. Body is rendered through `js/rich.js` (DOMPurify) only.
- `errors`: create-only with `hasOnly` + string-length checks; no auth required (public site); read admin; App Check enforcement later. Client throttles to 5 reports per page load and strips query strings from `url`.
- Service worker never caches cross-origin or non-GET, never caches `/admin/` HTML (admin always network-first), and skips requests with `Authorization`.
- Contact form has no backend: it builds a `wa.me` URL client-side (`httpsUrl`-style encoding), nothing stored.
- Backup workflow secret is a Firebase service account with Firestore read-only role (documented); the script never prints it.

## 5. Verification
- Unit: export list = rules collection set; head sync script idempotent; ics builder; sw version bump; error-report shape.
- Rules: `pages`, `errors` accept/reject.
- e2e: 404, each new page 200 + linked, share row, ics download, skip link, lightbox keyboard, tabs arrow keys, contrast pairs, export contents, audit viewer shows last edit, restore round-trip, masked re-auth, list search, last-updated stamps, static shell present with JS disabled (Playwright `javaScriptEnabled:false`), SW registers and offline home renders.
