# Phase 7 — Site Basics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close every *Build in Phase 7* item (1–44) of `docs/site-basics-audit-2026-09-12.md` so the site has everything a complete, user-friendly public site needs, with the audit's acceptance criteria as the definition of done.

**Architecture:** Same static site. New public pages are thin shells over a `pages/{id}` rich-text doc with code defaults (`js/page-defaults.js`) and one admin card 📄 পাতা. Static head tags and OG images are generated by scripts and checked in CI. A static app-shell in each HTML removes the layout shift; a versioned service worker caches the shell only. Admin gains an audit viewer, restore, masked re-auth, help links, search, previews, full export. Ops adds GitHub Actions CI, client error reporting to a bounded `errors` collection, and a secret-gated backup workflow.

**Tech Stack:** unchanged + GitHub Actions (ubuntu, Java 21, firebase-tools, Playwright), Lighthouse CLI for the final measurement.

Spec: `docs/superpowers/specs/2026-09-12-phase-7-site-basics.md`. Audit (acceptance criteria per item): `docs/site-basics-audit-2026-09-12.md` §2. Conventions: Phase 5/6 plans (subagent briefs, bridge CSS add-only, `el()` builder, `t()` keys for every string, `httpsUrl()` on every admin URL, admin section pattern, one build-log heading per task, docs in the same commit).

## Global Constraints

- All Phase 0–6 constraints bind: default-deny rules with tests; no hard deletes; `{bn,en}` fields; no `innerHTML` outside `js/rich.js`; every UI string is a `STRINGS` key (`t()`), every admin URL through `httpsUrl()`; bridge CSS add-only; `npm test` green before any rules deploy; one subject per commit with `docs/build-log.md`.
- **Acceptance = the audit's per-item "Accept:" line.** Each task lists its item numbers; the implementer proves each with a test, a measurement, or a `curl`, and records it in the report.
- New pages: `404.html privacy.html trust.html contact.html downloads.html news.html faq.html` (+ `refund` as a section of privacy AND a link on donate). All bilingual, all with the shared shell, all in the sitemap and footer "পাতা" column. Admin dashboard tile count → **17** (📄 পাতা) then **18** (📜 লগ) — update the tile-count assertions in the four specs each time.
- Static shell rule: the HTML contains real default markup for header/nav/hero-frame/footer; `js/shell.js` hydrates by replacing only the changed nodes; nothing may re-introduce the `…` full-page swap. CLS ≤ 0.1 measured.
- Service worker: same-origin GET only; never `/admin/*`; never gstatic/googleapis/firebasestorage; cache name `trust-shell-v<version>` where `<version>` is the string in `sw-version.js`, bumped by `scripts/bump-sw.mjs` and asserted by CI to differ whenever any cached asset changed since the last tag.
- `errors` rule: create-only, `hasOnly(['message','url','ua','stack','at'])`, each string bounded (`message ≤ 500`, `url ≤ 300`, `ua ≤ 300`, `stack ≤ 2000`), `at is timestamp`; read admin; client sends ≤ 5 per page load.
- Lighthouse targets (mobile, home): Performance ≥ 70, CLS ≤ 0.1, LCP ≤ 2.5 s, Accessibility ≥ 98, Best Practices ≥ 96, SEO 100.
